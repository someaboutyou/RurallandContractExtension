## 1. ISSUE-01 ✅ 已修 · 原问题描述：合户后原户的撤回入口断裂

| 项 | 内容 |
| --- | --- |
| **原状态** | 已用接口五环证实（`scripts/_verify_survey_merge_rollback.py`，PASS 38 / FAIL 0） |
| **现象** | 合户后，原户从主任务列表消失；在「已注销承包方」弹窗里**能看到它、按钮也能点，但点了必然 400** |

## 6. ISSUE-06 🔴 跨模块：户主编码口径错位（先定口径再改）

- **事实**：字典 `dictionary_items`（`nyt2539_c20_relation_to_head`）定义 **`01` = 本人、`02` = 户主**；
  但代码**到处按 `01` = 户主**实现。
- **受影响点**：
  - `contractor_service.py`：`is_household_head = relationToHead == "01"`
  - `services/survey/base.py`：`m.yhzgx == "01"`
  - `services/survey/household.py`：合户命中户主时把 `member.yhzgx = "01"`
  - `MergeHouseholdDialog.vue`：`yhzgx === "01"` 取默认户主
  - `MaintainMembersDialog.vue`：又把 `01` 标成"本人"（**自相矛盾**）
- **数据实测**：`yhzgx='02'` 有 **17.98 万**条、`='01'` 仅 **1** 条；60.2 万成员里 `is_household_head=true` **只有 1 条**。
- **后果**：
  1. 合户对话框取默认户主**恒落空** ⇒ fallback 到 `members[0]`（随便挑第一个成员）；
  2. 合户后只把该人标成户主，其余原户户主的 `yhzgx='02'` **原样保留** ⇒ **新户出现多个"户主"**。
- ⛔ **改动前必须先定口径**（到底是 `02` 还是 `01`），并评估存量 60.2 万成员的写法差异。
