# 多租户与数据权限说明

## 1. 当前租户定义

- 租户主表：`tenants`
- 当前系统以县级行政区代码作为租户编码
- 例如：`321324`

## 2. 核心规则

- 一个县对应一个租户
- 用户通过所属区域自动归属到某个租户
- 非平台管理员默认只能访问本租户数据
- 在本租户内，再按角色 `data_scope` 控制县、镇、村、本人范围

## 3. 已增加租户字段的表

### `tenants`

| 字段名 | 说明 |
| --- | --- |
| `code` | 租户编码，县级代码 |
| `name` | 租户名称 |
| `region_code` | 对应县级区域编码 |
| `status` | 状态 |
| `description` | 备注 |

### `regions`

| 字段名 | 说明 |
| --- | --- |
| `tenant_code` | 所属租户编码 |

说明：
- 县、镇、村三级区域会自动同步 `tenant_code`
- 省级区域可为空

### `users`

| 字段名 | 说明 |
| --- | --- |
| `tenant_code` | 用户所属租户编码 |

说明：
- 用户选择管理区域后，系统自动按区域所属租户写入 `tenant_code`

### `request_cases`

| 字段名 | 说明 |
| --- | --- |
| `tenant_code` | 申请单所属租户编码 |
| `region_code` | 申请单所属区域编码 |

说明：
- 创建申请单时，系统会根据 `FBF / CBF / CBHT` 编码自动推导租户和区域

### `request_case_participants`

| 字段名 | 说明 |
| --- | --- |
| `tenant_code` | 流程参与记录所属租户编码 |

说明：
- 参与记录会跟随申请单写入同一租户编码

## 4. 标准业务表的租户隔离方式

标准业务表目前没有新增 `tenant_code` 字段，仍按业务编码前缀隔离：

| 表名 | 隔离方式 |
| --- | --- |
| `fbf` | `fbfbm` 前 6 位 |
| `cbf` | `cbfbm` 前 6 位 |
| `cbht` | `cbhtbm` 前 6 位 |

说明：
- 这样可以兼容现有标准库，不改动原始业务表结构

## 5. 流程数据可见规则

### 平台管理员

- 可查看所有租户、所有区域、所有流程数据

### 其他用户

- 只能查看本租户数据
- 在本租户内，再按 `data_scope` 限定区域范围
- 流程数据还要满足以下条件之一：
  - 自己创建
  - 自己参与过
  - 当前流程节点正好是自己有权限办理的节点

## 6. 当前默认角色与典型范围

| 角色编码 | 数据范围 |
| --- | --- |
| `platform_admin` | 全部 |
| `county_auditor` | 县级 |
| `town_auditor` | 镇级 |
| `village_auditor` | 村级 |
| `operator` | 镇级 |

## 7. 当前实现位置

- 租户模型：`backend/app/models/tenant.py`
- 数据权限：`backend/app/services/data_access_service.py`
- 初始化与同步：`backend/app/db/init_db.py`
- 结构升级：`backend/app/db/migrations.py`
